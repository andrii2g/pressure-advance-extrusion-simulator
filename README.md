# Pressure Advance Extrusion Simulator

A deterministic .NET 10 educational simulator showing how pressure-advance feed-forward affects a deliberately simplified first-order extrusion plant.

This is control-theory teaching software. It is not printer-control software, a physical printer emulator, or a calibration authority for real hardware.

## Model

The requested volumetric flow uses a rectangular bead-area approximation:

\[
Q_r = vwh
\]

For the built-in motion profiles, its derivative is analytical:

\[
\frac{dQ_r}{dt} = wha
\]

Pressure advance forms the raw drive command before applying the selected drive policy:

\[
Q_{advance}=K\frac{dQ_r}{dt}
\]

\[
Q_{drive,raw}=Q_r+Q_{advance}
\]

The default `ClampToZero` policy produces:

\[
Q_d=\max(0,Q_{drive,raw})
\]

The plant is a single first-order pressure state:

\[
\frac{dP}{dt}=\frac{GQ_d-P}{\tau}
\]

\[
Q_{actual}=\frac{P}{G}
\]

The simulator uses deterministic fixed steps and explicit Euler integration. Signed flow error is always:

\[
e=Q_{actual}-Q_r
\]

Negative error means under-flow; positive error means over-flow. The full model and units are documented in [docs/model.md](docs/model.md).

## Commands

List the deterministic built-in scenarios:

```powershell
dotnet run -c Release --project src/PressureAdvance.Cli -- list-scenarios
```

Run one simulation:

```powershell
dotnet run -c Release --project src/PressureAdvance.Cli -- simulate --scenario corner --k 0.04
```

Compare K=0 with a selected K using identical motion, geometry, plant, timestep, and initial-pressure configuration:

```powershell
dotnet run -c Release --project src/PressureAdvance.Cli -- compare --scenario corner --k 0.04
```

Run an inclusive K sweep:

```powershell
dotnet run -c Release --project src/PressureAdvance.Cli -- sweep --scenario corner --k-start 0 --k-end 0.10 --k-step 0.005
```

Run from JSON configuration:

```powershell
dotnet run -c Release --project src/PressureAdvance.Cli -- simulate --config examples/default.json
```

Use `--help` for all options. Configuration precedence is CLI override, then JSON configuration, then built-in defaults.

Built-in scenarios are `acceleration`, `deceleration`, `trapezoid`, `corner`, and `multi-change`. The corner scenario models only a speed reduction and recovery; it does not model XY cornering dynamics.

## Reports

A simulation writes:

- `run.json`;
- `metrics.json`;
- `samples.csv`;
- `speed.svg`;
- `flow.svg`;
- `pressure.svg`;
- `flow-error.svg`.

A comparison also writes `comparison.svg` and retains both runs under `no-pa/` and `selected-k/`.

A sweep writes:

- `k-sweep.csv`;
- `k-sweep.json`;
- `k-sweep.svg`.

All machine-readable numbers use invariant formatting. SVG charts are generated directly by the reporting project without a chart package.

## Metrics

Each run reports:

- integrated absolute flow error (IAFE);
- signed minimum and maximum flow error;
- peak under-flow and over-flow magnitudes;
- RMSE;
- under-extrusion and over-extrusion volumes;
- clamp count;
- per-transition settling time and distance;
- aggregate worst settling time and distance.

Continuous metrics use trapezoidal integration over emitted samples. Settling requires the error to remain inside tolerance for the complete hold window.

## Verified default results

These values were generated by the Release implementation using the `corner` scenario, `tau = 0.040 s`, `dt = 0.001 s`, `G = 1`, 0.20 mm layer height, 0.45 mm line width, and `ClampToZero`:

| Run | IAFE (mm³) | Peak under (mm³/s) | Peak over (mm³/s) | RMSE (mm³/s) | Clamp samples |
|---|---:|---:|---:|---:|---:|
| K = 0 s | 1.283340 | 4.895694 | 5.616323 | 1.854865 | 0 |
| K = 0.040 s | 0.191450 | 0.000000 | 2.633862 | 0.439869 | 63 |

The measured IAFE reduction is 85.081934%. An inclusive sweep from 0 to 0.10 s in 0.005 s increments selects `K = 0.040 s`. At `K = 0.100 s`, IAFE rises to 1.126024 mm³ and peak under-flow rises to 0.708817 mm³/s, demonstrating over-compensation relative to the near-optimal run.

The relationship `K ≈ tau` belongs to this intentionally ideal first-order model. It is not a universal firmware conversion rule, a measurement of a real drive system, or printer-tuning advice. The rectangular area `w*h` is a pedagogical approximation rather than an exact slicer bead-volume model.

## Build and verify

```powershell
dotnet restore PressureAdvanceExtrusionSimulator.slnx
dotnet build PressureAdvanceExtrusionSimulator.slnx -c Release --no-restore
dotnet test PressureAdvanceExtrusionSimulator.slnx -c Release --no-build
```

The complete verification workflow is available in `scripts/verify.ps1`.

## Projects

- `PressureAdvance.Core` contains motion profiles, extrusion demand, feed-forward control, the first-order plant, simulation, metrics, settling analysis, and K sweeps.
- `PressureAdvance.Reporting` writes invariant CSV/JSON and standalone SVG charts.
- `PressureAdvance.Cli` resolves configuration and exposes the command-line interface.
- The two test projects cover numerical, behavioral, reporting, and CLI acceptance requirements.
